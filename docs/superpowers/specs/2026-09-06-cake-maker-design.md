# 케익 만들기 게임 설계

작성일 2026-09-06

## 무엇을 만드나

손님의 주문서대로 케익을 만드는 웹 게임. 제한 시간 안에 얼마나 정확히 만드느냐를 본다.
만든 결과가 주문과 얼마나 일치하는지에 따라 별 0~3개를 받고, 별점 비율만큼 돈을 받는다.
번 돈으로 새 재료를 해금하면 이후 주문이 그 재료를 포함해 점점 복잡해진다.

핵심 루프는 이것 하나다.

가게 준비(재료 구매) → 손님 받기 → 재료 고르고 계량 → 완성 → 별점·정산 → 다시 준비

## 왜 이 형태인가

- **시간 제한을 뒀다.** 처음에는 정확도만 보려고 뺐지만, 그러자 주문서를 느긋하게 베끼면
  누구나 별 3개가 나와 게임이 받아쓰기가 됐다. 세 축을 다 만들어 놓고 셋 다 공짜였다.
  시계가 돌면 재료를 고르고 순서를 지키고 수치를 맞추는 일이 모두 대가를 갖는다.
  시간이 다 되면 담긴 그대로 채점될 뿐 새 실패 규칙을 만들지 않는다.
- **선택과 계량을 섞었다.** 선택만 있으면 정답/오답 뿐이라 별 1~2개가 나올 자리가 없다. 계량이 연속적인 오차를 만들어 중간 별점을 자연스럽게 만든다.
- **그림을 코드로 그린다.** 케익 겉모습이 곧 레시피 데이터다. 이미지 파일을 쓰면 조합 수만큼 에셋이 필요하지만, SVG 조합이면 상태를 그대로 흘려보내면 된다.

## 기술 선택

빌드 도구 없는 순수 웹. 의존성 0개.

`<script type="module">`로 파일을 나눈다. 단일 파일은 900줄짜리 덩어리가 되어 손대기 어렵고,
Vite/React는 이 규모에 과하다. 모듈 분리의 대가는 `file://`로 열리지 않는다는 것 하나이며,
로컬 서버 한 줄(`python -m http.server`)로 해결된다.

채점 로직을 따로 떼어내야 테스트할 수 있다는 점이 이 선택의 이유다. 채점이 이 게임의 심장이다.

## 파일 구조

```
index.html          화면 뼈대
src/data.js         재료 카탈로그 + 해금 가격
src/order.js        주문 생성 (해금된 재료 안에서)
src/scoring.js      3축 채점 → 별점 → 금액   ← 순수 함수
src/cake.js         레시피 상태 → SVG
src/game.js         상태 + 화면 배선
test/scoring.test.js
```

`scoring.js`는 DOM도 게임 상태도 모른다. 주문과 결과를 받아 점수를 내는 것 외에 아무 일도 하지 않는다.

## 데이터 모델

재료 하나의 모양.

```js
{ id: 'choco-sheet', name: '초코 시트', type: 'sheet',
  measured: false, price: 200, unlockCost: 0 }

{ id: 'sugar', name: '설탕', type: 'filling',
  measured: true, unit: 'g', range: [50, 200], price: 50, unlockCost: 300 }
```

`type`은 `sheet` / `filling` / `topping` 셋. SVG 렌더링이 이 값으로 갈린다.
`measured: true`인 재료는 담을 때 수치를 정해야 한다.

주문서와 플레이어의 결과물은 같은 모양의 배열이다. 배열 순서가 곧 만든 순서다.

```js
[ { id: 'choco-sheet' }, { id: 'sugar', amount: 120 }, { id: 'cherry' } ]
```

## 채점

세 축을 각각 0~1로 구해 가중 합산한다.

| 축 | 가중치 | 계산 |
|---|---|---|
| 재료 | 60% | `교집합 크기 ÷ max(주문 개수, 결과 개수)`. 빠뜨림과 잘못 넣음이 모두 분모를 통해 감점된다 |
| 순서 | 15% | 맞은 재료들의 상대 순서. `최장 증가 부분수열 길이 ÷ 맞은 재료 개수`. 맞은 재료가 0개나 1개면 상대 순서를 이룰 쌍이 없으므로 이 축은 존재하지 않는다 |
| 계량 | 25% | 계량 재료별 오차율 `|내 수치 - 정답| ÷ 정답`의 평균. 10% 이내 만점, 50% 초과 0점, 사이는 선형 |

같은 재료를 여러 번 담을 수 있으므로 재료 비교는 집합이 아니라 **다중집합**으로 한다.
체리 5개를 주문했는데 3개만 담았으면 2개만큼 감점된다.

순서는 완전 일치가 아니라 **상대 순서**를 본다. 중간에 재료 하나를 빠뜨렸다고 그 뒤 전부가
틀린 것으로 처리되면 감점이 이중으로 들어간다.

별점 구간은 90 / 70 / 45점. 금액은 `정가 × 별점 ÷ 3`이며 별 0개는 0원이다.

**가중치 재분배.** 어떤 축이 그 주문에 존재하지 않으면(예: 계량 재료가 없는 주문)
그 축의 가중치를 남은 축에 비례 배분한다. 그러지 않으면 완벽하게 만들어도 별 3개가 나오지 않는다.

가중치·구간·오차 한계는 모두 `scoring.js` 상단 상수로 둔다. 이 숫자들은 계산으로 정하는 값이
아니라 플레이해 보고 감으로 맞추는 값이다.

## 화면

화면 전환 없이 한 페이지 3단. 상태에 따라 가운데만 바뀐다.

```
┌─────────────────────────────────────────────────────┐
│  🍰 케익 가게        💰 1,240원  주문 7번째  ⏱ 14초  │
├──────────────┬───────────────────┬──────────────────┤
│   주문서      │      작업대        │     재료 선반     │
│              │                   │                  │
│  손님 그림    │    ┌─────────┐    │  [초코 시트] 200 │
│              │    │ 만드는   │    │  [바닐라 시트]200│
│  초코 시트    │    │  케익    │    │  [딸기 크림] 150 │
│  설탕 120g   │    │  (SVG)   │    │  ─────────────  │
│  체리        │    └─────────┘    │  🔒 말차 크림     │
│              │                   │     해금 300원    │
│  정가 600원   │  넣은 것 (순서대로) │                  │
│              │  1. 초코 시트  ✕   │                  │
│              │  2. 설탕 110g ✕   │                  │
│              │                   │                  │
│              │   [ 완성! ]       │                  │
└──────────────┴───────────────────┴──────────────────┘
```

선반에서 재료를 누르면 작업대에 순서대로 쌓인다. 계량 재료면 슬라이더가 뜨고 수치를 정해야 담긴다.
**슬라이더에는 주문서 수치를 표시하지 않는다.** 주문서를 보고 맞추는 것이 계량의 전부인데
옆에 정답을 띄우면 게임이 사라진다.

### 시간

주문마다 제한 시간이 붙는다. 주문서를 읽는 시간에 재료마다 담는 시간을 더해 정한다.

    제한초 = 6 + 2 × 일반재료수 + 5 × 계량재료수

계량 재료가 더 무거운 것은 슬라이더를 맞춰야 해서 클릭보다 오래 걸리기 때문이다.
주문 크기에 비례하므로 해금이 늘어 주문이 길어져도 시간이 따라 늘어난다.
이 숫자들은 `order.js` 상단 상수이며 플레이해 보고 맞춘다.

시계는 주문이 뜨는 순간 시작해 완성을 누르거나 0이 되면 멈춘다. 결과 화면이 떠 있는 동안은
멈춰 있다. **계량 슬라이더가 열려 있는 동안에도 시계는 계속 간다** — 멈추면 슬라이더를 연 채로
무한정 생각할 수 있어 압박이 사라진다. 남은 5초부터는 숫자가 빨개진다.

0이 되면 완성 버튼과 **같은 경로**로 들어간다. 담긴 그대로 채점되고 결과 화면이 뜬다.
새 실패 규칙을 만들지 않는다 — 못 담은 재료는 재료 축이 알아서 깎고, 아무것도 못 담았으면
별 0개가 나온다. 다른 점은 코멘트가 "시간이 다 됐어요." 한 줄이라는 것뿐이다.
슬라이더가 열린 채 시간이 끝나면 그 창은 닫히고 그 재료는 담기지 않는다.

담을 때마다 가운데 SVG가 즉시 갱신된다. 시트는 층으로 쌓이고, 크림은 색을 덮고, 토핑은 위에 흩뿌려진다.
잘못 담은 것은 ✕로 뺀다. 완성 전까지는 아무 판정도 없는 되돌릴 수 있는 구간이다.

### 결과

```
        ⭐⭐☆
   재료 ●●●●●○  순서 ●●●●●●  계량 ●●●○○○

   "설탕이 좀 적네요."

        400원 획득      [ 다음 손님 ]
```

세 축을 따로 보여준다. 별 2개만 던지면 무엇을 틀렸는지 몰라 다음에도 같은 실수를 한다.
어느 축이 깎였는지 보이면 플레이어가 스스로 고친다. 한 줄 코멘트는 가장 많이 깎인 축에서 뽑는다.

### 준비 시간과 해금

게임은 두 상태를 오간다. **준비**는 시계가 멈춰 있는 시간이고, **제작**은 시계가 도는 시간이다.
가운데 버튼 하나가 상태에 따라 `다음 손님 받기` 와 `완성!` 로 바뀐다.

해금은 준비 시간에만 한다. 제작 중에 재료를 사게 하면 사는 데 쓴 시간이 주문 시간에서
빠져 해금이 성장이 아니라 벌칙이 된다. 시간 제한을 넣은 뒤에 드러난 문제였다.

**상점을 따로 만들지 않는다.** 선반은 이미 재료·가격·자물쇠를 다 보여주고 있어서,
시계가 멈춘 동안에는 그것이 곧 상점이다. 같은 정보를 두 군데 그리면 어긋날 자리만 생긴다.
준비 시간에는 선반 제목이 "재료 상점" 으로 바뀌고 테두리가 강조된다.

해금 즉시 다음 주문 생성의 후보로 들어간다. 재료 풀이 커지면 주문에 들어가는 재료 수도
함께 늘려, 난이도가 해금을 따라 자연히 올라가게 한다.

### 저장

`localStorage`에 돈과 해금 목록만 저장한다. 진행 중이던 주문은 버린다.

## 테스트

`scoring.js`와 `order.js`의 순수 함수만 테스트한다. 나머지는 눈으로 봐야 아는 것들이라
자동 테스트가 값을 못 한다. 제한 시간 계산은 순수 함수라 테스트하고, 카운트다운은 화면이라
테스트하지 않는다.

러너는 Node 내장 `node --test`. 의존성 0개를 유지하기 위해서다.

- 완벽히 일치 → 별 3개, 정가 전액
- 재료 하나 빠뜨림 / 하나 더 넣음 → 재료 축만 깎임
- 재료는 맞고 순서만 뒤집힘 → 순서 축만 깎임
- 계량 오차 10% 경계 → 만점, 50% 경계 → 0점
- 전부 틀림 → 별 0개, 0원
- 계량 재료가 없는 주문 → 가중치 재분배로 별 3개가 나와야 함
- 재료가 늘면 제한 시간이 늘고, 계량 재료가 일반 재료보다 시간을 더 받음

## 범위 밖

지금 만들지 않는 것들이다. 필요해지면 그때 붙인다.

- 콤보, 랭킹
- 설비 업그레이드·손님 수 증가 같은 경영 요소
- 사운드, 애니메이션
- 서버, 계정, 온라인 저장
